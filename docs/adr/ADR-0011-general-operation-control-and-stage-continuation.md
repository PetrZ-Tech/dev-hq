# ADR-0011 — Общий контроль операций и продолжение этапов

Дата: 2026-10-16. Статус: принято в рамках запроса пользователя на ремонт штаба.

Проблема: общий heartbeat и доступность инструментов не доказывают движение конкретного задания. Зависнуть может любая операция; обязательное подтверждение каждого подэтапа мешало исполнению уже согласованного плана.

Решение: до потенциально долгой операции исполнитель регистрирует её в текущем lifecycle run с ID, типом, сроком, источником результата и сведениями о side effect. Независимый Watchdog читает только этот run, проверяет срок и доступные источники, для локальных процессов — PID и время создания. Прогресс и наблюдение хранятся отдельно. Неизвестный исход не разрешает слепой повтор; незакрытые/повреждённые операции блокируют finish/prepare-report.

Новый существенный проект начинается с согласования архитектуры, ТЗ и этапов. Затем штаб проходит согласованный план с проверками и сохранением контрольных точек без повторного подтверждения каждого обычного шага. Scope/risk/manual gates и SECURITY_BOUNDARIES.md сохраняются.

Ограничения: регистрация кооперативная, прозрачного перехвата всех ChatGPT tools нет; универсальные status adapters удалённых плагинов и отдельный восстановительный исполнитель пока отсутствуют. Локальный монитор не работает при выключенном ноутбуке и не может сам продолжить остановленный ChatGPT turn. Action-key ограничен текущим run и не заменяет идемпотентность внешней системы. Старые skills/ChatGPT Sources могут требовать отдельной синхронизации; эта сессия не меняла SKILL.md.

Канонические контракты: OPERATION_CONTROL.md, STAGED_EXECUTION.md, TASK_LIFECYCLE.md, WATCHDOG.md. Проверки и ограничения: docs/audits/2026-10-16-operation-control.md.
