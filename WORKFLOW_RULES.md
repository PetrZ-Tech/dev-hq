# Workflow Rules

## Базовый цикл
Для существенной рабочей задачи использовать TASK_LIFECYCLE.md и scripts/task_lifecycle.py. По STAGED_EXECUTION.md сначала согласовать архитектуру и ТЗ нового проекта, затем выполнять согласованный план этапами с проверками и контрольными точками; продолжать без повторного подтверждения каждого шага.
1. Определи цель и тип задачи.
2. Выбери минимально достаточный инструмент по `TOOLS_REGISTRY.md`.
3. Получи контекст из Codebase Memory/репозитория/целевой системы.
4. Для существенных изменений кратко обозначь план.
5. Выполни изменение.
6. Проверь результат подходящим инструментом.
7. Зафиксируй важное изменение в памяти штаба, если оно влияет на будущую работу.
8. Закрой подэтап: результат + verification + checkpoint/state. Продолжай согласованный план при отсутствии реального блокера.
9. До потенциально долгого вызова любого инструмента зарегистрируй операцию по OPERATION_CONTROL.md; при timeout/неизвестном результате сначала read-only диагностика.

## Приоритет инструментов
- Структурированный API/MCP лучше браузерных кликов.
- UI Automation лучше координатной мыши.
- Прямое чтение файла лучше OCR/скриншота.
- Codebase Memory лучше повторного исследования известного локального проекта.
- Exa/Firecrawl использовать для внешних актуальных данных, а не вместо локального контекста.

## Изменения кода
- Сначала понять существующую архитектуру.
- Делать небольшие проверяемые изменения.
- После изменения запускать релевантный тест/линтер/build, если это разумно.
- Не коммитить и не пушить без явного запроса или заранее согласованного правила проекта.

## Безопасность
- Read-only: можно выполнять самостоятельно.
- Необратимые/массовые/публичные действия: подтверждение.
- Не изменять настройки безопасности ради удобства без отдельного согласования.
- Не сохранять секреты в репозиторий штаба.

## Рабочая и защитная зоны
- Главная автономная зона: `<PROJECTS_ROOT>\...`.
- Внутри `Projects` обычное редактирование кода, файлов проекта, тесты и build можно выполнять самостоятельно.
- Любое изменение вне `Projects` требует подтверждения пользователя.
- Системные настройки Windows, Registry, службы, Task Scheduler, firewall/network/VPN, драйверы, права доступа и установка/удаление программ всегда требуют подтверждения.
- Подробные границы см. `SECURITY_BOUNDARIES.md`.

## Актуальность состояния проекта
- При конфликте источников следуй `STATE_FRESHNESS.md`.
- Приоритет: live/runtime → локальные файлы и тесты → project state/context → Codebase Memory → Git/GitHub → README/docs → ChatGPT Sources/старые чаты.
- Если документация расходится с live-системой, явно пометь её устаревшей; не выдавай TARGET за CURRENT.
- Для n8n фактическое состояние через `n8n Connector` выше локального JSON/README.

## Handoff после существенной сессии
- Следуй `SESSION_HANDOFF.md`.
- После значимого изменения обнови `PROJECT_STATE.md` или существующий `PROJECT_CONTEXT.md`.
- Зафиксируй проверки, незавершённое и один следующий шаг.
- Затем переиндексируй изменённый проект в Codebase Memory.
- Если изменился общий статус проекта — обнови `PROJECTS_REGISTRY.md`.
