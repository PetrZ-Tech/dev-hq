# Memory Rules

## Что считать долговременной памятью штаба
- Файлы этого репозитория.
- Индекс Codebase Memory для `dev-hq`.
- Отдельные индексы Codebase Memory для конкретных проектов.
- Git-история штаба после того, как будет согласован режим коммитов.

## Что записывать
Записывать только то, что пригодится в будущих чатах:
- новые инструменты и их назначение;
- изменения инфраструктуры;
- новые проекты, статусы и пути;
- устойчивые рабочие правила;
- важные архитектурные решения.

Не записывать:
- одноразовые мелочи;
- секреты, ключи, пароли и токены;
- временные ошибки, если они не формируют полезный шаблон.

## Обновление памяти
После изменения реестров/skill-файлов переиндексировать `dev-hq` в Codebase Memory.
Если изменился отдельный проект — переиндексировать и его репозиторий.
После существенной рабочей сессии по проекту сначала обновить его `PROJECT_STATE.md`/`PROJECT_CONTEXT.md` по `SESSION_HANDOFF.md`, затем переиндексировать проект.
Codebase Memory не заменяет live-проверку: при конфликте следовать `STATE_FRESHNESS.md`.

## В новом чате
1. Прочитать/использовать инструкции ChatGPT Project.
2. При необходимости запросить Codebase Memory по `dev-hq`.
3. Для задачи по конкретному проекту дополнительно получить память соответствующего репозитория.
4. Не считать старый чат единственным источником истины.

## ChatGPT Project Sources
Sources в ChatGPT являются снимками файлов и не считаются автоматически синхронизированными с локальным репозиторием. После существенного изменения правил, инструментов, окружения или модельного роутинга обновить соответствующие Sources в проекте `Dev HQ`. Для оперативной актуальности главным источником истины остаются локальный репозиторий `dev-hq` и его индекс Codebase Memory.
