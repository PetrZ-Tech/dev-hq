# State Freshness Policy

Цель: не путать старую документацию с фактическим текущим состоянием проекта.

## Приоритет источников истины
При конфликте более высокий уровень имеет приоритет:

1. **Live system / runtime** — фактическое состояние целевой системы: n8n, Supabase/PostgreSQL, production/staging app, API, deployed service.
2. **Фактический локальный код и Git working tree** — файлы проекта, branch, status, тесты, build.
3. **PROJECT_STATE.md / PROJECT_CONTEXT.md** — последний явно зафиксированный handoff проекта.
4. **Codebase Memory** — оперативный индекс проекта; использовать вместе с `indexed_at` и переиндексировать после существенных изменений.
5. **Git/GitHub history / remote state** — commits, PR, issues, branch history.
6. **README / docs / architecture files** — описание и намерение; не доказательство текущего runtime-состояния.
7. **ChatGPT Project Sources / старые чаты** — снимки; использовать только как вспомогательный контекст.

## Правило проверки
- Если задача зависит от фактического состояния live-системы, проверять её специализированным MCP/API, а не доверять README.
- Для n8n: live `n8n Connector` выше JSON-экспорта и README.
- Для локального приложения: фактические файлы + тест/build выше PROJECT_STATE.
- Для GitHub: remote branch/PR state выше локальной заметки.
- Документация может описывать TARGET; всегда отличать `CURRENT`, `TARGET`, `VERIFIED`.

## Конфликт источников
Если найдено расхождение:
1. Не усреднять и не угадывать.
2. Явно написать, какой источник устарел.
3. Принять более свежий/авторитетный источник.
4. После существенной работы обновить handoff/state-файл проекта.
5. Переиндексировать проект в Codebase Memory.

## Маркеры уверенности
- `VERIFIED LIVE` — проверено в текущей целевой системе.
- `VERIFIED LOCAL` — проверено тестом/build/файлами локально.
- `RECORDED` — записано в state/docs, но сейчас не перепроверялось.
- `TARGET` — целевое состояние, не считать реализованным.
- `STALE` — известно, что запись отстаёт от факта.

## Что не считать доказательством
- наличие таблицы не доказывает работающий workflow;
- наличие workflow не доказывает успешный end-to-end run;
- наличие кода не доказывает успешный build/deploy;
- старый README не доказывает текущее live-состояние;
- ChatGPT Source не считается автоматически синхронизированным с локальным файлом.
