# Dev HQ — Quality Gate
Действующая политика команд: 2.0, 2026-10-16. Этот документ заменяет прежнее правило выбора команд только по имени script.

Назначение: обязательная проверка перед заявлением «готово», а также по команде «Проверь проект перед коммитом».

## Статусы и обязательные проверки

PASS — все применимые обязательные проверки прошли и критерии текущей задачи подтверждены.
WARN — проверка неполная, нет применимого test/lint/build или подтверждённых критериев.
FAIL — ошибка проверки, некорректная конфигурация, отказ preflight, изменившийся package.json, timeout либо невыполненный критерий.
Итог — худший из статусов.

Проверяются scope внутри <PROJECTS_ROOT>, Git/diff, добавленные строки и обычные untracked-файлы на признаки секретов, применимые automated checks, task acceptance и свежесть результата. Dirty tree сам по себе не FAIL. Значения найденных секретов не печатать; permission gates чтения чувствительных файлов сохраняются.

## Запуск

~~~powershell
python scripts/quality_gate.py --project <absolute-path> --criteria-ok yes --json
~~~

В JSON публикуется command_policy=2.0. --skip-exec выполняет разбор и проверку команд без запуска проверочных процессов; запрещённая цепочка всё равно даёт FAIL.

## План команд до исполнения

До запуска первой проверочной команды Gate разбирает все выбранные checks:
- автоматические npm scripts test, typecheck, lint, build;
- их pre/post hooks и транзитивные npm run ссылки;
- явно настроенные команды;
- применимые Python pytest или node test.js.

Циклы, отсутствующие ссылки, некорректный JSON/scripts, опасные имена/аргументы и неподдерживаемый синтаксис приводят к FAIL до выполнения checks. Нельзя незаметно пропустить опасный npm test и выдать PASS по другому fallback.

Разрешённые npm scripts разворачиваются в явные argv-шаги. Процессы npm/npx и shell со строкой команды не запускаются. Автоматические hooks не вызывают свои собственные hooks; явно названный npm run делает отдельный полный разбор.

Поддерживаются простые literal-команды и разделённые пробелами &&. Перенаправления, pipes, ;, одиночный &, подстановки, переменные окружения в команде, многострочный shell, inline Python/Node и неизвестные executables требуют отдельного review и не исполняются Gate.

npx допускается только в форме npx --no-install <известный check-tool>; исполняется уже установленный инструмент. Установка пакетов не выполняется. Для системного Python используется текущий интерпретатор; известные frontend tools ищутся в node_modules/.bin, затем PATH.

Проверочные режимы должны быть конечными: например vitest run и vite build. Watch, auto-fix и source-rewriting flags не относятся к автоматической проверке. Неподдерживаемая команда получает причину отказа; не обходить отказ переименованием script.

При изменении package.json после preflight Gate останавливается. После первой ошибки оставшаяся цепочка не выполняется. Общий бюджет automated checks — 1200 секунд на весь план, без автоматических retries.

## Конфигурация проекта

Необязательный .hq-quality-gate.json. Предпочтительны argv-массивы:

~~~json
{
  "commands": [
    {"name": "test", "command": ["npm", "run", "test"], "required": true},
    {"name": "build", "command": ["npm", "run", "build"], "required": true}
  ],
  "skip_auto_commands": true
}
~~~

Простые строковые команды сохраняются для совместимости и проходят тот же разбор. skip_auto_commands и required должны быть boolean, имена checks уникальны. required:false понижает ошибку самой проверки до WARN, но не ослабляет preflight.

Дополнительные аргументы npm run test -- ... поддерживаются для одного прямого check шага. Неоднозначная передача аргументов через вложенные npm aliases или && требует явных проверочных команд.

Зависимость от скрытого npm lifecycle environment, произвольных shell-команд или нестандартного CLI требует адаптации после review. Прямой запуск через другой инструмент допустим только в уже разрешённом объёме задачи; отказ Gate нельзя обходить ради формального PASS.

## Доверие и восстановление

Это структурная проверка плана для доверенного проекта, не sandbox произвольного JS/Python. Test entry point или установленный check-tool может содержать другой код; до запуска нужно проверить его назначение и сохранить реальные production/external-write/secret permission gates. Статический разбор команды не доказывает отсутствие сетевых вызовов внутри программы.

До потенциально долгого Gate зарегистрировать операцию по OPERATION_CONTROL.md. Gate не является самостоятельным исполнителем. После timeout/прерывания сначала прочитать тот же run, checkpoint и результаты. Побочный эффект с неизвестным исходом не повторять.

Gate не сохраняет durable checkpoint каждого внутреннего argv-шага. Для продолжения частичной работы сначала установить исход выполненных шагов, затем явно задать оставшиеся разрешённые checks. Перезапуск всего npm test может повторить pretest; это запрещено, пока исход его побочного эффекта неизвестен.

## Подтверждение результата

Критерии текущей задачи проверяются отдельно от exit code. Старый PASS не подтверждает изменённое дерево. Не выдавать PASS без содержательной проверки. После изменений применять TASK_LIFECYCLE.md: verify, gate, handoff, backup, memory и подготовленный отчёт с фактическим ответом пользователю. Commit/push/publish автоматически не выполняются.
